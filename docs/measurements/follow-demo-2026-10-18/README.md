# 主从 demo 兼容性恢复

角色保持白臂 `arm1` → 黑臂 `follower`，真实控制全部运行在远端计算机。
修正旧跟随配置的夹爪输出范围：旧 raw 1479–2982 已不适用于当前黑臂。
当前共享命令范围为 raw **464–1881**，位于操作者重新划定的原生
452–1893 范围内。白臂原有扳机端点 raw 1940–3002 保持不变。
配置快照见 [follow.json](follow.json)，转换与标定身份见 [mapping.json](mapping.json)。

白臂最初未枚举 USB，换口重插后已识别。读取又发现它的六轴零偏和五轴
原生限位与已有独立标定不一致。用户明确确认“没有机械调整，恢复已有标定对应设置”。
在六轴扭矩均为 0 时逐项恢复零偏和限位，读回验证并将 Lock 设为 1；
没有写入运动目标，也没有改原生 PID、Phase 或 Operating_Mode。
[恢复记录](arm1-restoration.json) 保留前后身份和全部实际写入。
重新打开串口后独立标定身份核对通过，白臂保持被动、六轴 Status=0。

本地完整回归 **794 passed, 1 skipped**，远端部署内容完整回归
**538 passed**，Ruff 检查通过。新增回归验证当前夹爪端点、半程映射与
黑臂当前姿态的初始化；历史端点测试明确使用历史范围，不再与当前配置混用。

实机预备阶段的白臂姿态对应黑臂接近或碰到桌面，因此保持状态下提示操作者
调整白臂，没有直接开始跟随。初始名义路径的几何核对不能替代连续跟随
中的现场观察。白臂 5/6 号同时曾出现间歇输入电压报警，程序保留 warning、
保持并等待显式恢复，没有关闭保护或把报警改成正常状态。
最终调整到抬高姿态后，按实际对齐逻辑采样核对初始名义路径，目标末端距桌面约
25.2 cm，随后完成慢速对齐并进入真机跟随。操作者反馈：“黑臂和夹爪都能跟随”。
实际 following 阶段记录约 48.8 秒，六轴均有输入和反馈变化；5 号活动幅度较小，
本轮不是逐轴性能验收。[曲线](live-follow.png) 与 [统计](live-follow-summary.json)
保留这一阶段；[压缩原始记录](live-follow.json.gz) 保留全程阶段和报警事件。
仅标定元数据中的本机绝对路径被规范化，所有控制帧保持原样，摘要分别记录源文件和发布 JSON 的哈希。

最终测试共记录 3 次白臂扳机输入电压报警，黑臂未记录故障事件。首次报警结束了
following 阶段，报警清除后仍保持，需显式恢复；之后未再次启用运动。
因此本次证明可以真机跟随，不能证明持续无故障运行，也未验证物理响应延迟。
采样至发命令 P95 约 6.07 ms，仅代表主机处理时间，不能当作电机响应延迟。

测试已保持并退出，临时只读显示已关闭。退出后重新打开双臂串口，12 个电机
均在线且 Status=0，独立标定身份匹配；白臂扭矩关闭，黑臂保持扭矩开启。
黑臂六轴原生 PID 未变，加速度与 Goal_Velocity 已恢复为测试前的 0。
见 [最终只读检查](final-preflight.json)、[原生参数读回](final-registers.json)。

再次运行可使用 `./scripts/lerobot-arm demo follow --start-held`，在控制终端输入
`e` 回车对齐并开始、`h` 回车保持、`q` 回车退出。开始前仍需确认现场空间与
当前白臂映射姿态；本次初始路径检查不代表任意连续跟随姿态均无碰撞。
